What still needs your browser

GoHighLevel workflow (draft only)

The workflow API is switched off for this account, so this is built in the builder. New workflow NB · Never-bought · Price lock, left in Draft:

  1. Trigger: tag added nb-price-lock. Filters: no Shopify order ever, not an active, paused or cancelled subscriber, email subscribed, not in WB · Win-back · One flow.
  2. Sale active check: if the Custom Value "Sale active" is yes, wait 1 day and check again.
  3. Webhook (POST) to the Deadline Funnel campaign webhook with email and first name. This starts the person's own 5-day timer.
  4. Send Price lock Email 1. Wait 2 days.
  5. Sale active check, then send Price lock Email 2. Wait 2 days.
  6. Sale active check, then send Price lock Email 3. Remove tag nb-price-lock.
  7. Goal: any Shopify order exits them.

Then open each of the three templates and swap in the Deadline Funnel timer image and tracking link. With the sale running 20 Nov to 1 Dec, nothing in this sequence can send in that window.

One gap to know about

Waits for Dana

Deadline Funnel enforces this deadline by redirecting the page, not by refusing a code at checkout, because the $84.99 is a plan price, not a discount. Someone who saved the intro product link, or got it from a friend, can still choose the $84.99 plan after their timer. That product is unlisted and has carried the $84.99 plan for a while, so this exposure already exists today.

A checkout-level block would need a new setup, for example a new Seal plan that renews at $89.99 plus a per-person code worth $5 off every renewal. Deadline Funnel codes cannot repeat on renewals, so that needs a different tool. Per your rule, I have not created any plan or price. This is only a spec until Dana decides.
